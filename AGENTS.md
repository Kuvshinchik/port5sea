# AGENTS.md

## 🎯 Цель
Определяет правила работы AI-агента с Laravel-проектом детской платформы.

Агент должен:
- писать расширяемый код
- учитывать будущие изменения (AI API, родительские аккаунты)
- не ломать существующую архитектуру

---

## 🧠 Основные принципы

- Работать малыми изменениями
- Не изменять код вне задачи
- Всегда учитывать масштабирование
- Не хардкодить бизнес-логику

---

## 🏗 Архитектура Laravel

Разделение строгое:

- Controllers → HTTP слой (тонкие)
- Services → бизнес-логика
- Models → данные
- FormRequest → валидация
- Jobs → AI / тяжёлые операции
- Events → расширяемость

❗ Запрещено:
- бизнес-логика в контроллерах
- прямые SQL-запросы вне моделей/репозиториев

---

## 🎮 Игры (Phaser интеграция)

Игры должны:

- быть изолированы от backend-логики
- получать данные через API
- не содержать бизнес-логику подписок

Backend:
- отдаёт JSON
- хранит прогресс

---

## 🤖 AI слой

Текущая реализация: локальная  
Будущая: API (например OpenAI)

Правила:
- всегда оборачивать AI в сервис (AIService)
- не вызывать AI напрямую из контроллеров
- использовать очередь (Jobs)

---

## 👶 Профиль ребенка

Текущая модель:
- ChildProfile = основной пользователь

Будущая:
- Parent → ChildProfiles

❗ Агент должен:
- не хардкодить отсутствие родителя
- писать код, допускающий связь parent_id

---

## 📚 Контент (БД)

Контент:
- хранится в БД
- фильтруется по:
  - возрасту
  - типу
  - категории

❗ Не хардкодить контент

---

## 💳 Подписки

- не хардкодить тарифы
- использовать конфигурацию или таблицу

---

## 🧪 Тестирование

Если тесты включены:
- писать unit + feature тесты
- покрывать:
  - сервисы
  - API

---

## 🖥 Среда

- Windows (OSPanel)
- учитывать пути Windows
- не использовать Unix-специфичные команды

---

## 🔄 Workflow

1. plan
2. implement step-by-step
3. test
4. explain changes

---

## 🚫 Ограничения

- не переписывать существующие модули без причины
- не добавлять зависимости без необходимости
- не менять структуру БД без миграции
